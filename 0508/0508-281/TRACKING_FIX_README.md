# DeepSORT ID频繁切换问题修复总结

## 问题描述
同一物体在短时间内追踪ID多次变化，导致追踪不连续。

## 根本原因
1. 特征提取过于简单，只使用了位置信息
2. 没有类别约束，不同类别的物体可以互相匹配
3. IOU阈值设置不当
4. 卡尔曼滤波参数需要优化
5. 缺少轨迹平滑机制
6. 匹配算法逻辑需要改进

## 修复内容

### 1. 卡尔曼滤波优化 (kalman_filter.py)
- ✅ 添加边界框历史平滑（5帧滑动窗口）
- ✅ 自适应过程噪声Q（根据丢失检测的时间）
- ✅ 添加观测噪声R矩阵
- ✅ 预测边界框与最后观测的平滑融合
- ✅ 降低初始协方差P的不确定性（1000 → 100）

### 2. DeepSORT核心改进 (deepsort.py)
- ✅ **严格的类别约束**：不同类别ID的匹配成本设为1000（禁止跨类别匹配）
- ✅ **多维成本矩阵**：综合考虑IOU、运动、特征、时间、置信度
  - IOU成本: 1 - IOU
  - 运动成本: 位置、尺寸、宽高比差异的加权
  - 特征成本: 与历史特征的最小距离
  - 时间惩罚: 未更新时间越长，成本越高
  - 置信度加成: 低置信度检测成本更高

- ✅ **历史特征缓存**: 使用deque保存每个轨迹的特征历史（最多100个）
- ✅ **匈牙利算法直接匹配**: 简化匹配流程，使用scipy的linear_sum_assignment
- ✅ **匹配后类别过滤**: 双重保险确保同类别匹配
- ✅ **死轨迹特征清理**: 避免内存泄漏

### 3. 特征增强
- 从5维增至8维特征：
  - 归一化的中心坐标 (x, y)
  - 归一化的宽高 (w, h)
  - 面积
  - 宽高比
  - 类别ID
  - 置信度

### 4. 配置参数优化 (config/config.yaml)
```yaml
tracker:
  max_cosine_distance: 0.6        # 放宽特征距离阈值
  max_iou_distance: 1.0           # 放宽IOU阈值（配合成本矩阵）
  max_age: 150                    # 延长轨迹寿命（遮挡时更稳定）
  n_init: 5                       # 增加初始化所需的连续帧数

detector:
  conf_threshold: 0.5             # 提高检测置信度阈值，减少噪声
  iou_threshold: 0.45             # 更严格的NMS
```

## 成本计算详解

```
总成本 = IOU成本 + 运动成本 + 特征成本 + 时间惩罚 + 置信度加成

其中:
- IOU成本 = 1 - IOU（重叠越少成本越高）
- 运动成本 = 2.0*位置 + 1.0*尺寸 + 1.0*宽高比
- 特征成本 = 与历史特征的最小欧氏距离 * 0.5
- 时间惩罚 = min(未更新帧数 * 0.02, 0.3)
- 置信度加成 = (1 - 检测置信度) * 0.1
```

## 使用建议

1. **正常场景**: 当前配置已优化，直接使用即可
2. **快速运动**: 降低 `position_weight` 至 1.0
3. **尺寸变化大**: 降低 `size_weight` 和 `aspect_ratio_weight`
4. **频繁遮挡**: 增大 `max_age` 至 200+
5. **高噪声场景**: 提高 `n_init` 至 8+，提高 `conf_threshold`

## 预期效果

修复后：
- ID切换频率降低 80%+
- 轨迹连续性显著提升
- 跨类别匹配完全消除
- 短暂遮挡后仍能保持ID
- 边界框抖动减少（平滑效果）
