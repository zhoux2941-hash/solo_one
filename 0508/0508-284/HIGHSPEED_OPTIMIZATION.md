# 高速网络拥塞控制优化

## 问题分析

在10Gbps网络且RTT=1ms的环境下，原拥塞控制算法存在以下问题：

1. **初始窗口太小**：10个包(~14KB)远小于带宽延迟积(BDP=1.25MB)
2. **慢启动增长太慢**：每个RTT只增加1个MSS
3. **CUBIC参数保守**：C=0.4导致拥塞避免阶段增长缓慢
4. **时间精度不足**：毫秒级精度无法准确测量1ms RTT
5. **最大窗口限制太低**：10MB不足以填满10Gbps长肥管道
6. **发送逻辑限制**：每次只发1个包，无法线速发送

## 优化方案

### 1. 双模式拥塞控制

- **高速模式**：RTT < 10ms时自动启用
- **普通模式**：保持原有行为

### 2. 高速模式参数优化

| 参数 | 普通模式 | 高速模式 |
|------|---------|---------|
| 初始cwnd | 10 MSS | 100 MSS |
| CUBIC C系数 | 0.4 | 0.8 |
| 丢包后乘性因子 | 0.7 | 0.85 |
| 最大cwnd | 10 MB | 100 MB |

### 3. 微秒级时间精度

- RTT测量使用微秒而非毫秒
- 拥塞窗口更新间隔动态调整(最小100us)
- 重传超时基于实际RTT动态计算

### 4. 慢启动优化

- 基于RTT的窗口增长缩放因子
- RTT=1ms时，每ACK最多增加5倍MSS
- 结合当前窗口大小的平方根因子，避免增长过快

### 5. 突发发送优化

- 单次事件循环最多发送64个包
- 充分利用高速网络的带宽
- 降低调度开销

### 6. 动态RTO计算

```
RTO = SRTT + 4 * RTTVAR
范围：5ms - 500ms
```

### 7. 更大的流量控制窗口

- 接收窗口从2MB增加到16MB
- 支持更大的带宽延迟积

## 预期性能提升

在10Gbps, RTT=1ms理想条件下：

| 指标 | 优化前 | 优化后 |
|------|-------|-------|
| 初始窗口 | 14 KB | 140 KB |
| 慢启动时间 | ~33 RTT | ~11 RTT |
| 最大吞吐量 | ~2 Gbps | ~9.5+ Gbps |
| 达到线速时间 | ~200ms | ~30ms |
| 最大cwnd | 10 MB | 100 MB |

## 使用方法

代码会自动检测网络条件并启用高速模式：

```cpp
// RTT < 10ms时自动启用高速模式
if (rtt_us < HIGHSPEED_RTT_THRESHOLD_US && !highspeed_mode_) {
    highspeed_mode_ = true;
    max_cwnd_ = DEFAULT_MAX_CWND_HIGHSPEED;
}
```

## 注意事项

1. **公平性**：高速模式可能对传统TCP流有一定不公平性
2. **丢包敏感性**：更大的cwnd意味着丢包后恢复时间更长
3. **CPU使用率**：突发发送可能增加CPU负载
4. **缓冲区**：确保网卡和系统缓冲区足够大
