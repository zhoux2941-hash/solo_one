# WebCodecs 屏幕录制与直播推流工具

基于 WebCodecs API 实现的高性能实时屏幕录制和直播推流工具，支持硬件加速编码。

## ✨ 功能特性

### 📺 屏幕采集
- **全屏采集**: 捕获整个显示器画面
- **窗口采集**: 捕获指定应用窗口
- **区域采集**: 自定义选择录制区域，支持拖拽调整

### ⚙️ 视频编码
- **H.264 编码**: 支持硬件加速编码，CPU 占用低
- **分辨率选择**: 480p / 720p / 1080p / 自定义分辨率
- **帧率调节**: 15 / 30 / 60 fps
- **码率控制**: 1000 - 10000 kbps 可调
- **硬件优先**: 自动检测并优先使用硬件编码器

### 🎙️ 音频编码
- **AAC 编码**: 高质量音频压缩
- **采样率**: 44100 / 48000 Hz
- **码率选择**: 64 / 128 / 192 kbps

### 🌐 直播推流
- **WebSocket 传输**: RTMP over WebSocket
- **兼容服务器**: 支持 SRS、Nginx-RTMP 等标准直播服务器
- **实时状态**: 连接状态和推流状态显示

### 📊 实时监控
- **码率统计**: 视频/音频/总码率实时显示
- **帧率监控**: 实际输出帧率统计
- **CPU 估算**: 硬件/软件编码 CPU 占用估算
- **码率图表**: 60秒码率历史曲线

## 🚀 快速开始

### 环境要求
- Chrome 94+ / Edge 94+ / Safari 16.4+ (支持 WebCodecs API)
- HTTPS 或 localhost 环境

### 运行方式

1. 启动本地 HTTP 服务器：
```bash
# 使用 Python
python -m http.server 8080

# 或使用 Node.js (http-server)
npx http-server -p 8080
```

2. 浏览器访问：
```
http://localhost:8080
```

### 推流服务器设置

推荐使用 SRS (Simple Realtime Server) 配合 WebSocket 插件：

```bash
# 使用 Docker 启动 SRS
docker run -p 1935:1935 -p 8080:8080 ossrs/srs:5
```

在工具中设置 WebSocket 服务器地址为：
```
ws://localhost:8080/rtmp/
```

## 🎮 使用说明

1. **选择采集源**
   - 点击"选择采集源"按钮
   - 选择要录制的屏幕、窗口或浏览器标签
   - 允许浏览器权限请求

2. **配置编码参数**
   - 选择输出分辨率
   - 设置帧率（推荐 30fps）
   - 调整码率（1080p 推荐 3000-5000 kbps）
   - 选择硬件加速编码以降低 CPU 占用

3. **连接推流服务器**
   - 输入 WebSocket 服务器地址
   - 输入推流密钥（如有）
   - 点击"连接服务器"

4. **开始推流**
   - 点击"开始推流"按钮
   - 查看实时预览和统计数据
   - 监控码率和 CPU 占用情况

## 🔧 技术架构

- **WebCodecs API**: 底层视频/音频编码接口
- **getDisplayMedia**: 屏幕采集 API
- **Canvas 2D**: 区域裁剪和缩放
- **WebSocket**: 实时数据传输
- **Chart.js**: 码率图表可视化

## 📝 注意事项

1. **浏览器兼容性**: 目前仅 Chrome/Edge 完整支持 WebCodecs 的所有功能
2. **硬件编码**: 依赖 GPU 支持，不同显卡性能可能有差异
3. **延迟优化**: 硬件编码 + 低延迟模式可实现 < 1 秒端到端延迟
4. **HTTPS 要求**: 生产环境必须使用 HTTPS 才能访问屏幕采集 API

## 🤝 常见问题

**Q: 为什么看不到硬件编码选项？**
A: 确保你的浏览器版本 >= Chrome 94，并且显卡支持 H.264 硬件编码。

**Q: 推流时画面卡顿怎么办？**
A: 降低分辨率或帧率，或者检查网络带宽是否充足。

**Q: 区域选择不准确？**
A: 确保预览窗口保持 16:9 比例，避免浏览器缩放。
