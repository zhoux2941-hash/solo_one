# 多路推流功能说明

## 🚀 功能特性

### 支持平台
- **自定义服务器**: 通用 WebSocket 服务器
- **B站直播**: B站直播平台（需要 WebSocket 转 RTMP 代理）

### 核心功能
- 同时推流到多个平台
- 每个平台独立的连接状态管理
- 每个平台独立的码率统计
- 开关控制每个平台是否启用
- 统一的连接/断开管理

## 📋 使用说明

### 1. 配置推流目标

#### 自定义服务器
- 勾选"自定义服务器"开关
- 输入 WebSocket 服务器地址（例如：`ws://localhost:8000/rtmp`）
- 输入推流密钥（如需要）

#### B站直播
- 勾选"📺 B站直播"开关
- 选择或输入 WebSocket 代理服务器地址
- 输入 B站 RTMP 推流地址
- 输入 B站推流密钥

### 2. 连接服务器
- 点击"连接所有服务器"按钮
- 观察每个平台的连接状态指示灯
- 绿色表示已连接，橙色表示连接中，红色表示未连接

### 3. 开始推流
- 选择采集源（屏幕/窗口）
- 配置编码参数（分辨率、帧率、码率）
- 点击"开始推流"按钮

### 4. 监控推流状态
- 查看"多平台推流统计"区域
- 每个平台显示实时码率和连接状态
- 总码率和 CPU 占用在顶部显示

## 🛠️ B站推流设置

### 获取推流地址和密钥
1. 打开 B站直播中心：https://live.bilibili.com/
2. 进入"我的直播间"
3. 点击"开始直播"
4. 在"直播设置"中找到 RTMP 推流地址和密钥

### WebSocket 代理
由于浏览器无法直接发送 RTMP 包，需要一个 WebSocket 转 RTMP 的代理服务：

- 代理服务器接收 WebSocket 连接
- 将 WebSocket 数据转换为 RTMP 协议
- 转发到 B直播服务器

### 本地代理测试
可以使用 Node.js 或 Python 搭建简单的代理服务，或者使用开源的 WebSocket-RTMP 桥接工具。

## 📊 状态说明

| 指示灯颜色 | 状态 | 说明 |
|-----------|------|------|
| 🟢 绿色 | 已连接 | 服务器连接正常，可以推流 |
| 🟠 橙色 | 连接中 | 正在尝试连接服务器 |
| 🔴 红色 | 未连接 | 连接断开或未连接 |

## 💡 性能优化建议

### 同时推流多个平台
1. **硬件编码优先**: 确保启用硬件编码，降低 CPU 占用
2. **码率适配**: 根据上行带宽调整总码率
3. **平台选择**: 只连接需要推流的平台

### 带宽计算
- 每个平台建议预留 10-20% 的额外带宽
- 同时推流到 N 个平台需要 ≈ N × 单平台码率

### 示例配置
- **1080p @ 30fps**: 码率 3000-5000 kbps
- **同时推流 2 个平台**: 建议上行带宽 ≥ 10 Mbps

## 🔧 故障排除

### 连接失败
1. 检查 WebSocket 服务器地址是否正确
2. 确认代理服务器是否运行
3. 查看浏览器控制台错误信息

### 推流卡顿
1. 检查编码队列大小（日志会显示丢帧情况）
2. 降低分辨率或帧率
3. 确保使用硬件编码
4. 检查网络上行带宽

### 码率显示为 0
1. 确认是否已点击"开始推流"
2. 检查编码是否正常工作
3. 查看浏览器控制台是否有错误

## 📝 开发说明

### 数据结构
```javascript
// 存储所有 WebSocket 连接
this.streamTargets = new Map(); // platformName -> WebSocket

// 每个平台的统计
this.platformStats = new Map(); // platformName -> { bytesSent, bitrate }
```

### 数据包格式
- 视频包: `[0x00] + H.264 数据`
- 音频包: `[0x01] + AAC 数据`

### 主要方法
- `connectPlatform()`: 连接单个平台
- `disconnectAll()`: 断开所有连接
- `updatePlatformStatus()`: 更新平台状态显示
- `updatePlatformBitrateDisplay()`: 更新码率显示
